The problem I help solve

You have a working model in COMSOL Multiphysics® simulation software. You know that tools such as Claude Code and OpenAI Codex are good at writing code. So you try “vibe-engineering”: you ask the AI to do the engineering work and accept what it produces. You then run into these problems:

  • The AI works clumsily with the software’s graphical user interface.
  • AI agents understand geometry and meshing poorly.
  • The AI suggests questionable physics and boundary conditions.
  • When the AI generates results, checking them takes you longer than running the simulation yourself would have.
  • You use AI as a better search engine, but you know that you could do more with agents.

How I work with COMSOL Multiphysics®

Every COMSOL Multiphysics® model is fully scriptable through the COMSOL® API for Java. AI coding agents that your team may already pay for can run parameter sweeps, design variants, supporting analyses, and postprocessing. Each change is recorded in an auditable log. This approach needs no new software, and you do not need to know Java.

I help you solve your actual engineering and physics problems. I work in a way that prepares you to run further studies with agents yourself. Those agents keep an auditable log of their changes, so that you can be confident in your results.

Featured demo · Free and open source

SpannBridge connects the Chatbot in COMSOL Multiphysics® software to Claude Code or OpenAI Codex

COMSOL Multiphysics® 6.4 has a built-in Chatbot window. SpannBridge is free, open-source software for Windows. It lets the Chatbot use the Claude or ChatGPT subscription that you already have, so you need no API key. Ask about your model, send Model Builder nodes and Graphics snapshots to the Chatbot, and run the COMSOL® API for Java code that the AI writes in the Java Shell.
